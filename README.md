# PomidorQA — Автотесты с марафона «Автоматизация на Playwright + TypeScript» 🍅

Репозиторий содержит базу автотестов (Unit, API и E2E), написанных мной в рамках марафона PomidorQA — сервиса 25-минутных встреч для QA/IT-специалистов. 

Продукт доступен как живой сайт: [aiqa.su/pomidorqa](https://aiqa.su). Здесь — только мои автотесты и вспомогательный код для них. Продукт тестируется как чёрный ящик: исходного кода приложения у набора нет, поэтому покрытие считается от функциональных требований, а не от строк кода.

## 🛠 Технологический стек
* **Тест-раннер:** Playwright
* **Язык программирования:** TypeScript
* **Статический анализ кода:** ESLint
* **Непрерывная интеграция:** GitHub Actions

## 🚀 Установка и запуск (Локально)

### 1. Установка зависимостей и браузеров
```bash
npm install
npx playwright install chromium
```

### 2. Запуск тестов
```bash
npm run test:unit   # Unit — без сети и без браузера
npm run test:api    # API — HTTP-запросы к локальному мок-серверу
npm run test:e2e    # E2E — реальный браузер на живом aiqa.su/pomidorqa
npm test            # Все три уровня сразу (Unit, API, E2E) — всего 33 теста
```

### 3. Просмотр отчетов и линтера
```bash
npm run lint        # Статический анализ кода (ESLint)
npm run report      # Открыть HTML-отчёт последнего прогона тестов
```

Стенд по умолчанию — продакшен. Переопределяется переменной окружения:
```bash
POMIDORQA_BASE_URL=http://localhost:3000 npm run test:e2e
```

## 📂 Структура проекта
* `src/pyramid/` — вспомогательный код: чистые функции и локальный мок-сервер для API-тестов.
* `tests/unit/` — тесты на пересечение слотов по времени, форматирование времени, валидацию пароля.
* `tests/api/` — тесты на регистрацию, бронирование, гонку за слот через HTTP к локальному мок-серверу.
* `tests/e2e/` — реальные сценарии в браузере (каталог, логика отмены, часовые пояса, гостевой доступ).
* `tests/helpers/` — генерация тестовых данных, Arrange через API и автоматический cleanup сессий.
* `tests/pages/` — Page Object: локаторы и действия конкретных экранов системы.

Разделение в коде жёсткое: в spec — сценарий и проверки, в helper — данные пользователя, в Page Object — экран. Локаторов в spec нет, expect в Page Object нет. Уровень проверки выбирается по риску: правила брони дешевле проверять запросом, а не кликами, поэтому они живут на API-уровне.

> **Оговорка про пирамиду:** unit-уровень во внешней автоматизации проверяет собственный код набора (файл `src/pyramid/slots.ts`), а не продукт. Широкое основание пирамиды здесь недостижимо, и это осознанный компромисс.

## ⚙️ Настройка CI (GitHub Actions)
В репозитории развернут и настроен собственный пайплайн непрерывной интеграции (`.github/workflows/playwright.yml`). При каждом событии **`push`** и **`pull_request`** автоматически запускаются:
1. **Typecheck and lint** — проверка стиля и ошибок кода через `npm run lint`. Браузер не поднимается, пока статика красная.
2. **Playwright tests** — полный прогон автотестов (unit, api, e2e) на Chromium с автоматическими ретраями для стабильности билда. Сводка метрик выводится в Summary прогона, а отчёты выгружаются в артефакты.

## 💡 Известные дефекты
Расхождения требований и продукта не спрятаны ради искусственно «зелёного» отчёта. Тесты на них написаны строго по ТЗ и помечены `test.fail()`:

| ID | Требование | Что происходит на самом деле | Тест |
|---|---|---|---|
| **KD-3** | R8.3: Каталог фильтрует только по навыкам «могу помочь» | Фильтр каталога ошибочно ищет по всем навыкам. Поиск находит тех, кто указал навык в блоке «хочу разобрать». | `e2e/skill-search.spec.ts` |

Пока дефект жив в продукте, ожидаемый результат теста — падение, и общий прогон остаётся зелёным. Когда баг починят на бэкенде, Playwright сообщит `expected to fail, but passed` — это будет сигналом снять пометку.

## 👩‍💻 Личный вклад
* На основе предоставленных заготовок полностью **адаптировала** проект под свой личный репозиторий, устранив расхождения в путях и архитектуре хелперов;
* **Интегрировала** сквозной сценарий гостевого доступа без регистрации (`e2e/guest-access.spec.ts`), проверив ограничения приватных страниц и валидацию формы авторизации при попытке забронировать слот;
* **Настроила** автотест для валидации часовых поясов (`e2e/slot-timezone.spec.ts`), контролирующий корректность отображения локального времени слота для хоста и гостя;
* **Перевела** очистку тестовых сред на автоматический трекер контекстов браузера (`contextTracker.cleanup()`), полностью исключив появление «мусорных» данных между прогонами;
* **Сформировала** финальную матрицу покрытия требований MVP и **свела** фактические метрики прогона (`33 тестов`) в единый инженерный отчёт.
